# OneCore acoustic backend: C port (src/zb_*)

Port of the HTS/SPS acoustic backend of `MSTTSEngine_OneCore.dll` 10.3.21207 (x64) for Microsoft David (float path)
and OneCore Zira / Mark (fixed-point path). Portable C99, bit-exact against the engine on the corpus in
`tests/backend/corpus.txt` (see "Status"). Companion notes: backend.md (map), backend_paramgen.md, backend_vocoder.md,
backend_io.md. Everything below that corrects or extends those notes is marked **[new]**.

## Input contract (what a frontend must produce)

Per sentence a `ZbUtt`: one `ZbPhone` per phone of the acoustic space (including the leading and trailing silence),
each with
* `f[ZB_NFEAT]`: the feature matrix row exactly as CTTSFeatureExtractionEngine slot 3 returns it, columns are the union
  of the three voices' APM feature paths (`zb_feature_path[]`). Null = `ZB_NULL` (-1).
  **[new] Null semantics** (FUN_180013ab0): a null cell compares as -1 in `==` / `in` questions and answers *no* to all
  ordering questions (`<=` etc.). Treating null as the integer -1 everywhere gives wrong durations.
* `c` (`ZbPhoneCtl`): the prosody block at phone+0x78 (+0 volume, +4 XML rate, +8 XML pitch, +0xc pitch-range float,
  +0x14 group ms, +0x18 phone target ms), silence / pause flags (FUN_18001d540 / FUN_18004d844), word index / type,
  and for the waveform stage: the word's NUS domain name (e.g. "phonenumber": [Domain] RateAdjustment), segment+0x40,
  word+0x90, and `sent_type` of the final silence (3 = yes/no question, Zira's QuestionIntonation).
  Plain-text defaults: volume 100, everything else 0, `phone_ms` 100 on the leading silence and
  [SilenceLength] SentenceBoundary (David 750, Zira/Mark 500) on the trailing one; pauses carry their ms too.
* `ZbSapi`: ISpVoice::SetRate / SetVolume.

Golden dumps: `harness/zbtap.exe "text" out.wav log.bin <token> [rate] [volume]` (records documented in zbtap.c and
zb_io.c). `zb_load_zbtap()` reads the matrix, per-phone attributes and the reference stages (DUR, VUV, LF0, LSF,
GAIN, F0 after export, int LSF chunks, PCM). `zb_load_ziraprobe()` reads the text output of `harness/ziraprobe.exe`
(matrix only, plain-text defaults for the attributes; bit-exact for plain text, verified).

## Numerics / build

* IEEE single and double, no contraction, no excess precision: MSVC `/fp:precise` (x64 and x86/SSE2 both verified),
  gcc/clang `-ffp-contract=off -fno-fast-math` (`-msse2 -mfpmath=sse` on 32-bit x86). The MSYS2 UCRT64 gcc build is
  bit-exact too.
* libm: the engine calls UCRT `exp`, `cos`, `pow`, `powf`, `logf`, `sqrt`. `powf(3, k/10)` and `powf(2, k/24)` for the
  duration rate and pitch are tabulated (the UCRT values are the correctly rounded ones); the noise table (sin/log/sqrt
  at init) is embedded. Remaining runtime calls: `exp` (F0 export, gain, soft clip), `cos` (LSF->LPC), `pow` (SAPI
  volume, waveform rate speed `powf(3, r/10000)` evaluated as a correctly rounded double pow), `logf` (domain rate),
  `sqrt`. With a libm whose double `exp`/`cos` round differently from the UCRT a last-ulp difference is possible; none
  was observed with MSVC x64/x86 (UCRT) or MSYS2 UCRT64 gcc.
* CRT `rand()`: `s = s*214013 + 2531011; (s>>16) & 0x7fff`, seeded 0x406 at load and after every utterance. The engine's
  state is per thread; the port keeps it per voice.

## Float path (David) [new details]

* Durations: the rounding carry of FUN_1800692d0 is **not** reset per phone (it runs over the whole utterance).
* Silences: target frames = `(16000/1000*ms)/80`; silence phones put the difference on the middle state (FUN_1800a4710).
* UV weight = max over the state's streams of the MSD weight (only David's F0 has 3 streams).
* MLPG, F0 smoothing, export, pitch: as in backend_paramgen.md; transcribed literally (zb_mlpg.c, zb_synth.c).
* Vocoder blocks: excitation and synthesis run per synthesis block (FUN_180009b14 grouping: same stretch flag and XML
  rate, <= longest phone of the utterance in frames, first block of a chunk <= 2 phones). The pulse tracker is *not*
  block invariant (a pulse falling before the block start is clamped to sample 0), so the port reproduces the blocks.

## Fixed-point path (Zira, Mark) [new]

* APM runtime records: F0 state = file `{f32 w, i16 mean[3], u8 prec[3], pad}`, runtime weight
  `(short)(int)(w*16384.0f + 0.5f)` (Q14). LSF state = 156-byte record, decoded by FUN_1800451a0 with **T = 75
  (3 windows)**: static u8 cumulative means x8 (Q15), i16 gain; delta/delta-delta i8 x4 read at byte `i+1` (so the
  delta-delta reads start one byte early, overlapping the delta gain's high byte: replicated), i16 gains at bytes
  `i + i/25`. Precision `2*p^2` (static, min 2) or `2*256*p^2` (dynamic); F0 static uses `p^2>>2`.
* The int predictors use **all three windows** (predictor +0x20 = 3/75), so FUN_18000c0f0 takes the generic branch
  (the 2-window fast path with the [1 2 1]/4 smoothing described in backend_paramgen §4.1 is never used by Zira/Mark):
  - W^T P W and W^T P mu in integers: window coefficients `(int)(c*16)`, `R += ((P>>1)*mean*c16)>>4`,
    `W[t][k] += (int)(((int)(c_k*16) * ((int)(P*c16)>>4))>>4)` (FUN_18000c6d0),
  - LDL^T in double (the same routine as the float path) on `(double)W`, back to int: `D = (int)D`,
    `L = (int)(L*2^28)`,
  - substitution in int64 (FUN_18000bd90): `g = 2R - (sum L*g >> 28)`, `g = (D/2 + g)/D`, back `x = g - (sum L*x >> 28)`,
  - LSF: frames whose delta precision is 0 in runs of >= 2 take the static mean; last dim (gain) x10. F0: x7 (Q15 log F0).
* UV: FUN_1800a49a0 on Q14 weights, threshold `(short)(0.5*16384+0.5)`, `n = (w*d + 0x2000) >> 14`.
* F0 chain: FIR (weights `(int)(w*32768)`, products `(x*w)/32768` truncating, result `(all*acc)/used`), EnhanceRate in
  Q15, QuestionIntonation (Zira): anchor = first voiced frame at/after the first phone of the last syllable of the last
  word when the final word node has sentence type 3 (runtime-verified: "Is it raining?" -> 'n', "... homework?" -> 'w';
  wh-questions are type 4, no ramp); linear ramp `+0.005*32768` per frame capped at `5.35*32768`, then an 11-tap
  boxcar (taps 0xba2) over +-20 frames. Export: Hz = `table800[min((lf0+128)/256, 799)]` (DAT_180188140).
  Pitch / pitch range on integer Hz (FUN_1800a0fac / FUN_1800a274c; mean = unsigned sum / count).
* LSF generation is streamed (LSPDecomposing DelayMode=1, FUN_180110394 -> FUN_18010f584): chunk k starts at phone s,
  takes `first = s ? 4 : 1` phones, then the split phone is the argmax over the next <= 7 phones of
  `(d_k + d_prev)^2 / (|d_k - d_prev| + 5)` (d = phone frames, d_prev starts at 0); if fewer than 4 phones would remain
  the chunk takes all. MLPG runs over `[s - 3, end + 3)` (overlap 3 phones of context each side, clipped) and only the
  chunk's own frames are kept. Each chunk is then vocoded (edge copy on the first/last chunk, int LsfSharpen, int LSF
  repair whose frame 0 is the chunk's first frame) block by block.

## Waveform rate change (Sonic)

Status: bit-exact on all David corpus items with positive speaking rates (items 90, 92, 93, 103, 105, 108, 110-114;
`tests/backend/sonic_replay.c` also replays every logged Sonic call bit-exactly). Code: `src/zb_sonic.c`, `src/zb_wave.c`,
flag output in `zb_durations_ex` (`src/zb_dur.c`).

* Which segments are stretched: every segment (phone+0xd8) starts with the flag +0x4c = 1. The duration predictor's rate
  step (FUN_18006cda8) clears it when MixRateScale rescales the phone to `(uint)(sum/f)` frames, which only happens when
  that is > nStates (5). So for slow rates everything is done in the durations; for fast rates a short phone (sum/f <= 5)
  keeps its unscaled durations and flag 1, and the wave stage time-compresses it with Sonic at speed
  `powf(3, r/10)`, r = clamp(clamp(xmlRate,-10,10) + siteRate, -20, 20) (FUN_18004e254; one powf of the summed rate,
  unlike the durations which multiply two powf values). Flag-0 blocks, or rate 0, pass through.
* Blocks (FUN_180009b14): consecutive phones with equal (flag, xml rate), total frames <= max phone frames of the utterance
  (output buffer size, FUN_18010e7c8), and the first block of the utterance holds at most 2 phones.
* Per block (FUN_18004dd00, CWaveGenerator+0x160 = previous block rate, 0 after a flag-0 block): if rate != previous or
  flag == 0: flush Sonic (slot 5 = process(NULL,0,flags 2)); flushed samples get a 240-sample fade-out on their tail
  (CWaveSmoother FUN_1801052cc, ramp k/240; resampled ramp `w[(int)(i*(239/(n-1))+0.5f)]` when shorter) when
  VoiceSetting.MixRateScale != 0 (David). Rate 0: output = flushed + block, block head faded in (only if something was
  flushed). Rate != 0: setSpeed, write block, flush only if the block's flags == 2 (last block and not first block;
  a single-block utterance is never flushed), read everything; output = Sonic output, or flushed + Sonic output with the
  fade-in on the Sonic part (if Sonic produced nothing: flushed + the unstretched block). The Sonic stream and the
  previous rate persist across utterances (one CRateChangerSonic per wave generator).
* After the rate stage: voice volume (SpsVolumeAdjustment 180 for David) on the whole block, then per-segment SAPI volume
  on segment lengths redistributed over the block output (FUN_1801050c0: running float sum, floor(acc+0.5), last segment
  takes the remainder).
* Sonic = Bill Cox's Sonic (2011-2015 C version: `sonicCreateStream(16000,1)`, pitch = rate = volume = 1, quality 0,
  useChordPitch 0): minPeriod = sr/400 = 40, maxPeriod = sr/65 = 246, maxRequired = 492; pitch search on a 4x
  down-sampled buffer (sum of 4 samples / 4, C truncation) over [10, 61], refined on the original samples within +-16,
  AMDF with 16-bit absolute differences and **unsigned 32-bit** comparison products; prevPeriodBetter with
  preferNewPeriod = 1; skip/insert pitch period with integer overlap-add `(down*(n-t) + up*t)/n`; flush pads
  2*maxRequired zeros and truncates the output to `nout + (int)(nin/speed + 0.5f)`.
* Not covered: NUS units (+0xe0), MSTTS.SpeakRate / absolute rate (WinRT SpeakingRate), domain RateAdjustment, and the
  FUN_18004e460 head trim (wavegen+0x21c, NUS junction) - none occur for plain SAPI text.

## Waveform rate change (CRateChanger, Zira/Mark)

Status: bit-exact. Zira 115/115, Mark 115/115, David unchanged at 115/115. All 185 logged CRateChanger calls replay
exactly (`tests/backend/rc_replay.c`, built by `tests/backend/build_replay.bat`). Code: `src/zb_ratechg.c`,
`src/zb_wave.c`, INI key `VoiceSetting.WaveScale` (cfg `wavescale_sonic`). Harness records: `'RSPD'` (f64 speed) and
`'RPRC'` (same layout as `'SPRC'`), taken from CRateChanger vtable 0x180171280 slots 1 and 4.

* Which changer is used: Zira and Mark have no `WaveScale=Sonic`, so `CWaveGenerator+0x98` is a plain `CRateChanger`.
  They have no MixRateScale either, so:
  * durations are never rate-scaled;
  * every segment keeps stretch flag 1;
  * any non-zero block rate is applied on the waveform;
  * no CWaveSmoother ramps are applied.
* Block logic (FUN_18004dd00) is the same as for Sonic. The rate-changer calls map as follows:
  * slot 5 flush (FUN_180153690) returns nothing when no samples are pending, otherwise it is `process(NULL, 0, flags 2)`;
  * slot 1 setSpeed (FUN_180153860) resets the stream when the speed changes;
  * slot 4 process takes the block flags (bit 0 = first block of the utterance → reset first; bit 1 = last block → flush at the end).
* Fine rate mode: the wave generator runs in fine mode (+0x20c) and FUN_18004e254 returns rates in 1/1000 steps.
  * rate = clamp(1000·xml + segment+0x40, ±10000) + 1000·site rate + round_away(10·1000·logf(pct/100)/logf(3)), clamped to ±20000.
  * pct = RateAdjustment + domain RateAdjustment − 100, using FUN_180067e20. The domain RateAdjustment comes from the word's NUS domain, e.g. "phonenumber" → 80.
  * The percent term is skipped when word+0x90 == 1.
  * speed = powf(3, (float)(rate/10000.0)). Example: phone numbers on Zira run at speed 0.80001229, not 3^-0.2.
  * For integer rates this gives the same values as the coarse mode that David's Sonic path used.
* CRateChanger is SOLA in double precision. Parameters (FUN_180052298, scaled by sr/8000):
  * frame N = 440;
  * synthesis hop L = 160;
  * overlap V = 80;
  * search range K = 200;
  * analysis hop Sa = (int)(160·speed).
* First frame (FUN_18015d81c): output frame[0..L) as is and keep frame[L..L+V) as the overlap. If the first call cannot
  fill a frame, its input passes through unchanged and is not kept.
* Per frame:
  * lag = (L − Sa) + previous lag. Only if that falls outside [0, K], search again (FUN_1800259d0): maximise c²/E for c > 0, where c is the dot product of frame[lag..lag+V) with the overlap and E is the running energy of that window. Accumulation is sequential in double; ties keep the first lag.
  * Crossfade: frame[lag+i] = ((V−i)·ov[i] + i·frame[lag+i]) / V.
  * New overlap = frame[L+lag..+V); output frame[lag..lag+L) as (short)(int); input position advances by Sa.
* Leftover input (fewer than N samples) is stored as int16. On flush, the last partial frame is handled by FUN_18015d860:
  * search limit = min(K, m−V−1);
  * crossfade length = min(V, m−lag);
  * output frame[lag..m).
  The stream is then reset.
